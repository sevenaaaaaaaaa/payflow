# 芭乐派矩阵 · PayFlow / LearnFlow 定位 brief

> 本文档与 OpenFlow 仓库 `docs/PRODUCT-MATRIX.md` 保持同步。红线：任何宣传页不得把其他
> 产品写成「本产品的某个模块」；互通走 API，拔掉任何一个其余照常。

## PayFlow

- **独立价值主张**：卖数字产品/订阅的人，要的不是增长系统，是「能收钱」。
  PayFlow 只做这一件事并做到极致：一行嵌入，全球可用，结算清楚。
- **差异化边界**：
  - 对 OpenFlow：全家桶用户 PayFlow 内嵌可用；但 PayFlow 独立售卖，零母体依赖
  - 对 Webs Flow：Webs Flow 做承接页，PayFlow 做收款——表单即支付是互通点不是依赖
  - 对 MFlow：内容分发带货，购买链接是互通点
- **必须做出来的成绩**：
  1. 一行嵌入（`<script src="payflow.../checkout.js" data-product="...">`）三分钟上线
  2. 订阅自动续费 + 失败重试 + 降级提醒完整闭环
  3. 推荐码/佣金结算可审计、可提现
  4. 首批支付通道 ≥2 家可用
- **收割人群**：知识付费创作者、独立开发者、讲师

## LearnFlow

- **独立价值主张**：讲师要的交付闭环：上课→进度→测验→证书→复购。不给增长 OS，给交付。
- **差异化边界**：
  - 对小鹅通类：轻、可无头、数据可迁移
  - 对 PayFlow：交付域 vs 收款域，API 互通
  - 对 OpenFlow：全站 CMS 在 OpenFlow；LearnFlow 只管课程交付
- **必须做出来的成绩**：
  1. 开营到结业全流程（报名→学习→作业→证书）一页后台管完
  2. 视频播放流畅（Range 分段 + 防下载）
  3. 完课率看板 + 学习曲线
- **收割人群**：讲师、教练、训练营主理人

## 互通原则（五个产品一致）

1. 一切互通走公开 API（HMAC / API Key），不共享数据库
2. 每个产品独立可用
3. 互通是增益而非依赖：宣传页不得出现「必须先装 X」
